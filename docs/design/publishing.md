# Publishing

How the mod reaches Windhawk users and how a new version ships. The reasoning is in [[decisions/publishing|Publishing decisions]]; the mod itself is described in [[design/mod|Mod behaviour]].

## Where the mod is published

The mod is in the Windhawk mod catalogue at [windhawk.net/mods/mute-focused-window](https://windhawk.net/mods/mute-focused-window), where users install it from Windhawk itself. The catalogue is built from [ramensoftware/windhawk-mods](https://github.com/ramensoftware/windhawk-mods), which holds the published source as `mods/mute-focused-window.wh.cpp`. Version 1.0 was accepted on 2026-10-22 through [ramensoftware/windhawk-mods#6456](https://github.com/ramensoftware/windhawk-mods/pull/6456).

`main` in this repository is the source of truth. The published file must be byte-identical to [mods/mute-focused-window.wh.cpp](../../mods/mute-focused-window.wh.cpp) as merged here. Changes are never made only in windhawk-mods.

## Shipping an update

1. Change the mod here through the normal PR process. In the same PR, raise `@version` to a new number made of digits and dots; windhawk-mods rejects a version it has published before. The gate must pass.
2. Once that PR is merged, check the file with windhawk-mods' own validator:
   - It's `.github/pr_validation.py`, run with its `extract_mod_symbols.py` and `preprocessor.py` beside it. It needs Python 3.12 or newer and PyYAML; uv's managed Python works on Cicely's machine.
   - Run it from this repository's root: `python <validator>/pr_validation.py mods/mute-focused-window.wh.cpp cicely-f 8198623`. The last two arguments are the PR author's GitHub login and user ID.
   - It must report no warnings.
3. Sync the fork [cicely-f/windhawk-mods](https://github.com/cicely-f/windhawk-mods) with upstream (`gh repo sync cicely-f/windhawk-mods`). Branch from its `main`, copy the merged file over `mods/mute-focused-window.wh.cpp`, and commit only that file. windhawk-mods uses the commit message for the mod's changelog, so name the version and the changes.
4. Open the PR against `ramensoftware/windhawk-mods` `main` from the `cicely-f` account, as a draft per Cicely's rule. Keep the repository's PR template intact. For an update, the description must contain a non-empty changelog between the `<!-- changelog:start -->` and `<!-- changelog:end -->` markers.
5. Comment `/ai-review`. The windhawk-reviewer bot posts an AI review. Both reviews for 1.0 took under ten minutes; the Windhawk wiki allows 20–30 minutes or more.
   - Treat its findings as suggestions to verify.
   - Make real fixes here first, through steps 1–3.
   - Answer the rest in a reply. Every reply written by an AI must include "Generated by AI. Model: …", naming the model.
6. When the review is settled, Cicely marks the PR ready for review and comments `/ready-for-reviewer`, which hands it to a human maintainer. The bot refuses that command on a draft, and before any AI review.
7. Any push to the PR takes it out of the human queue. Each push needs a fresh `/ai-review`, then `/ready-for-reviewer` again.

## Rules windhawk-mods enforces

The validator and the review process check these, beyond the gate here:
- **One file per PR:** the PR changes only `mods/mute-focused-window.wh.cpp`.
- **Fixed identity:** `@id` never changes.
- **Author link:** `@github` must be exactly `https://github.com/cicely-f`, the account that opens the PR.
- **Versioning:** every update needs a new `@version` and a changelog in the PR description.
- **Encoding and line length:** the file is UTF-8 without a byte-order mark, with no line longer than 4096 characters.
- **Tool mods:** a tool mod, which this is, must not declare `@architecture`.

## Tooling pitfalls

These came up while publishing version 1.0 from the Git Bash tool on Cicely's machine:
- **Leading slashes:** Git Bash rewrites any argument that starts with `/` into a Windows path. A `gh pr comment --body "/ai-review"` posted `C:/Program Files/Git/ai-review` instead. Prefix such commands with `MSYS_NO_PATHCONV=1`; the same applies to git sparse-checkout patterns.
- **Sparse clone:** a full clone of windhawk-mods isn't needed. A shallow clone with `--filter=blob:none` and a sparse checkout of the mod's own path is enough to commit the file.
